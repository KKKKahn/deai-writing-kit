# 示例：一条诊断明细长什么样

> 以下为虚构示例，演示阶段一报告中"单条问题"的标准写法。

## 条目 D3-01

- **位置**：评述正文第 1 段第 2 句（开头句"本文主要介绍……"之后）
- **原文照引**：「综上所述，DeMamba 不仅在性能上取得了显著提升，而且在计算效率方面表现出色，展现出广阔的应用前景。」
- **痕迹类型**：D3 空洞形容词堆砌 + D2 对仗排比（"不仅……而且……"）+ D1 模板化结尾（"综上所述""广阔的应用前景"）
- **判定理由**：
  1. 一句话里同时出现"综上所述、不仅……而且、显著、出色、广阔前景"五个高频 AI 套话信号，密度异常；
  2. "显著提升""表现出色""广阔前景"都是删掉后不损失任何信息的"正确的废话"，没有给出任何具体数字或个人判断；
  3. 真正刚读完论文的研一学生，结尾通常会带着具体困惑（比如"我没搞懂它为什么在 XX 数据集上反而变差"），而不是给出一段工整的广告式总结。
- **严重度**：高（P0）
- **改写对照**：

| AI 腔原句 | 研一学生写法 |
|---|---|
| 综上所述，DeMamba 不仅在性能上取得了显著提升，而且在计算效率方面表现出色，展现出广阔的应用前景。 | 整体看下来，DeMamba 的效果确实比原始 Mamba 好一点，速度也快了一些，不过我还没太搞懂它在长序列任务上到底为什么会更占优，这个后面我再查一下。 |

**修改手法说明**：删掉全部评价性套话；加入第一人称（"我还没太搞懂""我再查一下"）；把笼统的"显著提升"弱化为口语化的"好一点、快了一些"；用一个真实的疑问收尾，符合新手"带着问题结束"的状态。

## 元数据检查示例（对应报告第四节）

| 字段 | 实际值 | 是否可疑 | 处理建议 |
|---|---|---|---|
| dc:creator | Codex | 是 | 改为作者本人姓名 |
| dc:description | 「基于用户原稿、两份评审和论文PDF修改…」 | 是（直接暴露 AI 工作流） | 删除 |
| dc:subject | 论文评述辅助修改 | 是 | 删除 |
| dc:title | DeMamba论文评述（修改稿） | 是 | 改为"DeMamba论文评述" |
| TotalTime | 0 | 是 | 按字数估算或指定分钟数 |
| Words / Characters | 0 / 0 | 是 | 从正文真实重算 |
